# AFPA 프로젝트 개요 및 전체 설계

> AFPA (AI Financial Planning Agent, 프로젝트명 "금융아빠")
> 이 문서는 프로젝트 전체를 한 번에 파악하기 위한 **총괄 문서**다. 세부 내용은 각 링크 문서가 기준이며, 충돌 시 「AFPA 로드맵 및 구현 순서」와 「설계 파라미터 결정표」를 따른다.
> 상태: 설계 단계 (일부 초안). 담당: 김주영, 김성용

---

## 1. 프로젝트 개요

### 1.1 한 줄 정의
사용자의 목표를 기준으로 **저축·대출·투자·부동산을 하나의 경로로 통합 설계**하고, 규제와 제도를 반영한 실행 가능한 계획으로 자산을 안정적으로 늘려 가며, 상황이 바뀌면 스스로 갱신하는 **금융 관리 agent**.

### 1.2 해결하려는 문제
- 자산·소비 정보가 여러 금융사에 흩어져 있어 재무 상태를 한눈에 파악하기 어렵다. (진단)
- 목표(내 집 마련, 결혼 등)에 대해 "얼마를, 언제까지, 어떻게" 모아야 하는지가 구체적 행동으로 연결되지 않는다. (계획)
- 예적금·대출·투자·부동산 의사결정이 서로 영향을 주는데, 기존 서비스는 도메인별로 따로 다룬다. (통합)
- 대출 규제, 자격 요건, 세제 혜택처럼 **실제로 받을 수 있는 것**을 일반 사용자가 판단하기 어렵다. (제도)
- 계획을 세워도 실행되었는지 추적되지 않고, 상황이 바뀌어도 갱신되지 않는다. (지속)

### 1.3 핵심 가치

**서비스 정체성 (agent로서의 차별점)**

| 가치 | 설명 | 도입 |
| --- | --- | --- |
| **통합 자산 성장 설계** | 하나의 목표 아래 저축·대출·부동산·투자를 한 경로로 설계하고 선택지를 비교한다. 도메인별 기능을 합치지 않고 통합 플래너가 도메인 모듈을 호출하는 구조 | 2차~ |
| **자산 성장 경로와 시나리오** | 순자산이 N년 뒤 어떻게 늘어나는지 보여 주고, What-if(저축 변경·지출 이벤트·소득 변화·수익률 가정)로 비교한다 | 2차 |
| **규제·제도를 반영한 실행 가능성** | 이 사용자가 실제로 받을 수 있는 대출 한도(DSR/LTV), 가입 가능 상품, 세제 혜택을 규칙표로 판정해 현실적인 선택지만 제시한다 | 3차~ |
| **부동산 목표 설계** | 구매력 분석, 전세·월세·매매 비교, 취득 비용 포함 자금 계획, 청약·정책 상품 | 4차 |
| **이행 추적과 갱신** | 제안을 실행했는지 추적하고 경로 이탈 시 재계산·재제안한다 (승인 후 적용) | 2차~ |
| **선제적 관리** | 사용자가 묻기 전에 기회·위험·시점을 찾아 제안하고, 이행 이력으로 개인화한다. 자율 수준은 사용자가 정한다 | 6차 |

**기반 역량 (일반 금융 플랫폼 수준)**

| 가치 | 설명 |
| --- | --- |
| 진단 | 마이데이터 기반 금융 프로필 (금융 건강도 = 현황, 금융 잠재력 = 전망) |
| 설명 가능성 | 모든 제안에 근거(이유·사용자 수치·적용 규칙·기준일) 제공 |
| 안전성 | 계산·판정은 코드, LLM은 설명과 조합. 실제 금융 행위는 agent가 직접 실행하지 않음 |

### 1.4 사용자 가치 메시지 예
- "5년 안에 전세보증금 2억을 만들려면, 지금 속도로는 8개월 부족해요. 적금 우대 상품과 월 저축 15만 원 증액을 함께 하면 1년 2개월 앞당길 수 있어요."
- "이 목표에는 청약 납입과 정책 대출 자격이 연결돼요. 현재 DSR 기준 가능한 대출 한도는 이만큼이에요."

## 2. 전체 구조

### 2.1 구성

```
                       ┌──────────────────────────────┐
 사용자 금융 프로필 ──▶ │        통합 플래너 (2차)        │ ◀── 목표 관리
                       │ 경로 · 시나리오 · Action Plan    │
                       │ · 이행 추적 · 재계산             │
                       └───────┬───────────────┬──────┘
            선택지(Option)     │               │   가능 여부 판정
   ┌───────────────┬───────────┴──┐     ┌──────┴────────────────────┐
   │ 예·적금 (3차)   │ 대출·부동산 (4차)│     │ 규제·제도 규칙 엔진 (3차)    │
   │               │ 투자 (5차)      │     │ 대출 규제 · 자격 요건 · 세제  │
   └───────────────┴────────────────┘     └───────────────────────────┘
          ▲ 외부 정보 수집 (3차~)        ▲ 소비 변화 / 환경 변화 모니터링 → 재설계
                       │
              자율성 고도화 (6차): 선제 제안 · 개인화 · 자율 수준
```

| 모듈 | 역할 | 입력 | 출력 |
| --- | --- | --- | --- |
| 사용자 금융 프로필 | 현재 금융 상태 파악, 모든 모듈의 기본 정보 | 온보딩 + 마이데이터 | 자산·소비 요약, 건강도·잠재력 |
| 목표 관리 | 장기 목표·Life Event·부동산 목표 관리 | 사용자 입력 + 프로필 | 목표 리스트, 달성 가능성, 부족 자금 |
| **통합 플래너** | 자산 성장 경로, 시나리오, Action Plan, 이행 추적 | 프로필, 목표, 도메인 선택지 | 경로, Action Plan, 추천 근거 |
| **규제·제도 규칙 엔진** | 대출 규제·자격·세제 판정 | 사용자 정보, 행동 후보 | 가능 여부·한도·사유(규칙 ID·기준일) |
| 금융 정보 수집 | 외부 상품·정책·시장 정보 수집·변경 추적 | 외부 소스 | 사용자 맞춤 금융 정보 |
| 도메인 모듈 | 예·적금 / 대출·부동산 / 투자 선택지 생성 | 프로필, 목표, 외부 정보 | 선택지(현금흐름 효과·수익 모델·근거) |
| 소비 변화 모니터링 | 소비 패턴 변화 감지 | 스냅샷 이력 | 구조적 변화 이벤트 |
| 금융 환경 변화 모니터링 | 금리·상품·정책·규칙 변경 감지 | 수집 정보 변경 이력 | 영향도 |
| 계획 재설계 | 변화 반영 계획 재생성 | 위 이벤트, 이행 이탈 | 변경 전/후 비교, 승인 요청 |
| 자율성 (6차) | 선제 제안·개인화·자율 수준 | 모든 이벤트·이행 이력 | 선제 제안 |

## 3. 로드맵 (구현 순서)

> 기준 문서: 「공통 설계/AFPA 로드맵 및 구현 순서」. 차수는 **구현 순서**이며 "MVP"는 별도 의미가 없다.

| 차수 | 이름 | 핵심 내용 | 외부 데이터 |
| --- | --- | --- | --- |
| **1차** | 기본 플랫폼 | 연동, 자동 분류, 금융 프로필, 수입·지출·자산 분석, 목표 관리 | 없음 |
| **2차** | **통합 플래너** | 자산 성장 경로, 시나리오, Action Plan, 이행 추적, 소비 변화 모니터링, 단순 재설계 | 없음 |
| **3차** | **규제·제도 엔진 + 예·적금** | 규칙표, 정보 수집, 예·적금 전략, 환경 변화 모니터링, 대출 데이터 수집 추가 | 시작 |
| **4차** | **대출·부동산** | 구매력 분석, 전세·월세·매매 비교, 대출 전략, 청약 | 시세·규제 |
| **5차** | 투자 | 투자 성향, 자산 배분, 연금·절세 포트폴리오 (종목 추천 없음) | 시장 |
| **6차** | **자율성 고도화** | 선제 제안, 자율 수준 설정, 개인화 | — |

**순서의 이유**
- 2차 통합 플래너는 외부 데이터 없이 만들 수 있고, 이후 모든 도메인이 이 경로 위에 얹힌다.
- 3차 규칙 엔진은 대출·부동산의 전제다. 외부 수집 파이프라인은 구조가 가장 단순한 예·적금으로 먼저 검증한다.
- 부동산(4차)은 "내 집 마련"이 대표 목표이기 때문에 투자(5차)보다 앞선다. 투자는 규제·법적 부담이 가장 크고, 저축·대출·부동산 경로가 잡힌 뒤에야 여력이 의미를 갖는다.
- 자율성(6차)은 앞 차수의 씨앗(이행 추적 → 환경 변화 알림)을 묶어 완성한다.

### 1차 범위
- **포함:** 온보딩 + 마이데이터(수신·카드·증권, 테스트 데이터), 자동 분류, 금융 프로필(6개 엔진), 수입·지출·자산 분석, 목표 입력·관리·달성 가능성(단순형)
- **제외:** Action Plan, 리밸런싱, 시나리오, 이행 추적, 모니터링, 외부 데이터 기능

## 4. 모듈별 설계 요약

### 4.1 사용자 금융 프로필 (1차)
> 상세: `프로젝트/사용자 금융 프로필_1차 MVP 버전/` (분류 로직, 산출 로직, DB 스키마, 온보딩 설계)

**데이터 흐름:** 온보딩 입력 + 마이데이터 → 자동 분류 → 프로필 산출 → 스냅샷 저장

**① 입력**
- 온보딩(마이데이터로 알 수 없는 정보만): 생년월일, 고용 형태, 거주 형태·월세, 지역, (선택) 성별·투자 성향
- 수동 자산: 보유 현금, 금 현물, 기타
- 마이데이터(1차): 은행 수신, 카드, 증권. 대출 정보는 3차에 추가
- 개발 단계에서는 표준 API 규격 기반의 직접 만든 테스트 데이터 사용

**② 자동 분류** — 5개 대분류

| 대분류 | 분류 기준 (1차 = 구조화 필드 / 보조 = 텍스트) |
| --- | --- |
| 자산 | 계좌유형 코드로 현금성·저축성·투자·연금, 상품명 키워드는 세분류 보조. ISA는 내부 자산으로 분해, 금 현물은 수동 입력 |
| 부채 | 상환방식·대출 종류 코드, 카드 결제예정·할부 잔액 |
| 수입 | 3~6개월 입금의 주기성(±3일)·금액 일정성 + 적요 키워드 |
| 고정지출 | 3~6개월 출금의 주기성(±3일)·금액 유사성 + 가맹점명 키워드 |
| 변동지출 | 가맹점·MCC로 카테고리 매핑 |

가맹점 분류는 폴백: 가맹점명 유무 분기 → 코드 정확매칭 → 키워드 규칙 → **LLM 추론** → 사용자 직접 수정(이후 자동 적용). 동의 게이트: 가맹점명·적요·상품분류는 항목별 동의가 필요하며, 1차는 전체 동의 전제.

**③ 프로필 산출 — 6개 엔진**

| # | 엔진 | 산출물 |
| --- | --- | --- |
| 1 | 현금 흐름 | 월 가용 소득, **월 여유 자금**(사용자 노출 대표 지표) |
| 2 | 자산·부채 건전성 | 순자산, 자산 유동성 비중, DSR 유사지표, 부채 비율 |
| 3 | 비상금 충당 | 필요 비상금(기본 3개월, 프리랜서·자영업 6개월), 충당률 |
| 4 | 소비 진단 | 소비 성향 지수, 카테고리 비중, 이상 지출 |
| 5 | **금융 건강도** (현황, 100점) | 저축/투자 30% · 부채 관리 30% · 비상금 20% · 소비 통제 20% |
| 6 | **금융 잠재력** (전망, 100점) | 목표 진척 속도 35% · 저축 여력 30% · 소득 성장성 20% · 시간 여유 15% |

**④ 저장 스키마 (6개 테이블):** users, user_profiles, financial_snapshots(이력 누적), mydata_consents, merchant_category_overrides, manual_assets. 재무 지표는 단일 컬럼이 아니라 **스냅샷 이력**으로 누적한다(경로 추적·모니터링의 기반).

### 4.2 목표 관리 (1차, 유형 분화는 4차)
> 상세: `프로젝트/목표 관리/목표 관리 설계.md`

- **유형:** 일반 목표·Life Event(1차), 은퇴(2차 이후 검토), 부동산(4차: 희망 지역·주택 유형·거래 형태·가격대)
- **기능:** 생성·수정·삭제, 우선순위, 필요 자금 계산, 달성 가능성 분석(1차 단순형)
- **계산:** `월 필요 저축액 = (목표 금액 − 현재 금액) / 남은 개월 수` → 3차 복리 반영 → 이후 물가·시세 반영
- 2차부터 통합 플래너가 목표들을 하나의 경로로 묶는다.

### 4.3 통합 플래너 (2차)
> 상세: `프로젝트/사용자 목표 맞춤형 금융 planning-2차/2차 통합 플래너 설계.md`

- **자산 성장 경로 엔진:** 목표별 월 배분과 기준·개선·시나리오 경로, 단순 수익률 가정(보수적)
- **시나리오 엔진:** 저축 변경, 지출 이벤트, 소득 변화, 목표 변경, 수익률 가정 → 기준 대비 차이로 비교
- **Action Plan:** 지출 개선(불필요한 소비 탐지·절약 항목·목표 대비 소비), 자산 리밸런싱(R-01~R-03: 비상금 우선·투자 가능 비중·단기 목표 자금). 모든 제안에 **목표 경로 효과** 표시
- **이행 추적:** 실행 확인(자동/체크), 경로 이탈 감지 → 재계산 제안(승인 후 적용), 거절 사유 학습
- **도메인 모듈 인터페이스:** 선택지(현금흐름 효과·수익 모델·규칙 판정·근거) 규격. 3차 이후 모듈이 여기에 붙는다.

### 4.4 규제·제도 규칙 엔진 (3차)
> 상세: `공통 설계/규제·제도 규칙 엔진 설계.md`

- **범주:** 대출 규제(DSR/LTV), 자격 요건(청년 상품·청약·정책 대출), 세제(ISA·IRP·연금저축·이자 과세), 취득 비용, 상품 한도
- **구조:** 규칙은 조건 + 파라미터의 선언적 표현, 출처·시행일·검증일 보유. 규칙 변경은 코드 수정 없이 규칙표 갱신
- **판정 함수:** `loan_capacity`, `eligible_products`, `tax_effect`, `acquisition_cost` — 결과에 적용 규칙 ID·기준일·근거 수치 포함
- 판정은 코드, LLM은 설명만 한다.

### 4.5 외부 정보 수집과 예·적금 (3차)
> 상세: `프로젝트/사용자 목표 관련 금융 정보 수집/`, `planning-3차/3차 규제·제도 엔진 및 예·적금 설계.md`

- **수집:** 상품·정책·시장 정보 → 정규화 → 필터링 → 변경 이력(→ 환경 변화 모니터링)
- **예·적금 모듈:** 추천, 금리·우대금리 비교, 만기 시뮬레이션, 리밸런싱, 세후 효과(규칙 엔진), 통합 플래너 선택지로 연결(목표 달성 시기 변화)

### 4.6 대출·부동산 (4차)
> 상세: `planning-4차/4차 대출·부동산 전략 설계.md`

- **흐름(내 집 마련):** 구매력 분석 → 전세·월세·매매 비교 → 취득 비용 포함 자금 계획 → 자금 조달(저축 경로 + 대출 + 청약·정책 상품) → 시점 최적화(시나리오) → 이행·갱신
- **구매력:** 자기자본 + 대출 가능 한도(규칙 엔진) − 취득 비용, 상환 후 여유 자금 검증
- **대출 전략:** 상품 비교, 상환 방식·순서, DSR/LTV 반영, 정책 상품 자격

### 4.7 투자 (5차)
> 상세: `planning-5차/5차 투자 전략 설계.md`

- 투자 성향(설문), 자산 배분, 리밸런싱, 연금·절세 포트폴리오. **종목 추천 없음**, 수익률은 가정 범위로만 제시. 착수 전 법무 검토

### 4.8 모니터링과 재설계 (2차 → 3차 → 6차)
> 상세: `프로젝트/사용자 소비 변화 모니터링`, `금융관련 정보 변화 모니터링`, `모니터링 결과 기반 계획 재설계`

| 모듈 | 감지 | 판정 |
| --- | --- | --- |
| 소비 변화 (2차) | 카테고리 급증·급감, 신규 정기결제, 수입 변화 | **구조적**(2개월 연속·신규 정기결제) vs **일시적**(1개월 후 복귀·일회성 지정). 구조적만 알림·재설계 |
| 환경 변화 (3차) | 금리·상품·카드 혜택·규제·정책·**규칙표 변경** | 사용자 매칭 → 금전·일정 영향도 |

**재설계 흐름:** 재평가 → 트리거 판단(달성 시기 ±2개월 또는 월 여유 자금 ±10%) → 플래너 재호출 → 변경 전/후 비교 → **사용자 승인 후 적용**. 변경 이력은 `plan_versions`로 보존.

### 4.9 자율성 고도화 (6차)
> 상세: `planning-6차/6차 자율성 고도화 설계.md`

- **선제 제안:** 경로 이탈 임박·기회·위험·시점·생애 이벤트 트리거 → 근거와 "왜 지금인지" 포함
- **자율 수준(사용자 설정):** L0 제안만(기본) / L1 소액 자동(한도 내 계획 갱신 후 통보) / L2 승인 후 실행 연계. 실제 금융 행위(이체·가입·해지·매매)는 agent가 직접 실행하지 않는다
- **개인화:** 이행·거절 이력과 알림 반응으로 제안 방식 조정(열람·초기화 가능)

## 5. 공통 설계

### 5.1 LLM 역할 경계
> 상세: 「공통 설계/LLM 사용 원칙 및 추천 표현 가이드」

| LLM이 하는 일 | 코드가 하는 일 |
| --- | --- |
| 분류 4단계(불명확 가맹점 추론, 캐시) | 모든 금액·비율·점수 계산, 경로·시나리오·이행 이탈 |
| Action Plan 조합·우선순위 설명 | 분류 1~2단계 규칙, 주기성 감지 |
| 추천 이유·알림 문구·시나리오 해설 | **규제·자격·세제 판정(규칙 엔진)**, 선제 트리거 감지 |
| 재설계 호출 | 변경 감지·영향도 계산, 알림 빈도 제어 |

원칙: **LLM은 계산하지 않는다.** 출력 수치는 코드 결과와 일치하는지 검증한다. 식별 정보·계좌/카드번호는 전달하지 않는다. 종목 추천·수익 보장 표현 금지.

### 5.2 알림
> 상세: 「공통 설계/알림 설계」

유형: 소비 변화 · 환경 변화 · 계획 재설계 제안 · 이행·경로 이탈 · 선제 제안 · 목표 마일스톤. 등급별 즉시·일일 요약·주간 요약. 재설계·선제 제안은 승인/거절이 필요하며 거절 후 30일 재제안 금지.

### 5.3 개인정보·마이데이터
> 상세: 「공통 설계/개인정보 보호 및 데이터 파기 정책」

최소 수집, 컬럼 단위 암호화, 로그·LLM 전달 시 비식별화, 연동 해지 시 수집 원본·분류 결과 삭제, 항목별 동의 저장. 법정 기한·스냅샷 해지 후 처리는 법무 확인 후 확정. 개인화 데이터도 동일 정책 적용.

### 5.4 평가
> 상세: 「공통 설계/평가 기준 및 성능 대시보드」

분류 정확도, 지표·경로 골든 케이스(오차 0), 시나리오 일관성, 규칙 엔진 회귀, Action Plan 체크리스트, 이행 추적 판정 정확도, 선제 제안 수용률. 테스트 데이터는 페르소나별 3명(user_001~003)과 정답 라벨.

### 5.5 설계 파라미터
> 상세: 「공통 설계/설계 파라미터 결정표」

정의(D-), 임계치(P-), 리밸런싱(R-), 통합 플래너·자율성(E-)을 ID로 관리. 주요 값: 주기 허용 ±3일(영업일 보정), 이상지출 +20% & 월 소득 1% 이상, 월 저축액 = 당월 신규 납입액, 노출 대표 지표 = 월 여유 자금, 자율 수준 기본값 L0.
