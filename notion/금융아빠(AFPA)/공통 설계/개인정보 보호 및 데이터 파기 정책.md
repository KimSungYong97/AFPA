# 개인정보 보호 및 데이터 파기 정책

> AFPA — 마이데이터 연동 데이터와 사용자 개인정보의 처리 원칙
> 상태: **초안**. 법적 요건(보관·파기 기한, 마이데이터 사업자 의무)은 **법무·컴플라이언스 확인 후 확정**한다. 이 문서는 설계 원칙을 정한다.

---

## 1. 원칙

1. **최소 수집:** 서비스에 필요한 필드만 수집한다. 1차는 기본 범위(수신·카드·증권)만.
2. **목적 제한:** 수집 목적(재무 진단, 목표 계획) 외 사용 금지.
3. **암호화:** 저장·전송 모두 암호화. 식별 정보(이메일·이름·전화·생년월일)는 컬럼 단위 암호화.
4. **비식별화:** 분석·로그·LLM 전달 시 식별 정보를 제거한다.
5. **파기:** 연동 해지·탈퇴 시 데이터를 삭제한다(아래 3절).

## 2. 데이터 분류와 처리

| 분류 | 예시 | 저장 | 로그 | LLM 전달 |
| --- | --- | --- | --- | --- |
| 식별 정보 | 이메일, 이름, 전화, 생년월일 | 암호화 | **금지** | **금지** |
| 금융 원본 | 계좌번호, 거래내역 원문, 카드번호 | 암호화, 계좌·카드번호는 마스킹 저장 | 금지(마스킹도 최소화) | 계좌·카드번호 금지 |
| 가맹점·적요 | 가맹점명, 적요 | 암호화 | 금지 | **분류 4단계에서만** 가맹점명 단독 전달(금액·일시·사용자 ID 제외) |
| 산출 지표 | 건강도, 비율, 스냅샷 | 일반 저장 | 사용자 ID 해시와 함께만 | 집계 수치만 |

## 3. 연동 해지·탈퇴 시 파기

| 대상 | 처리(안) |
| --- | --- |
| 마이데이터 수집 원본 (계좌·거래·카드·증권) | 해지 즉시 접근 차단, **지체 없이 삭제** (기한은 법무 확정) |
| 분류 결과·사용자 수정 이력 | 원본과 함께 삭제 |
| `financial_snapshots` (산출 지표) | 해지: 삭제 또는 비식별 통계로 전환 중 **정책 선택 필요** |
| 목표·Action Plan | 사용자가 입력·생성한 것이므로 해지만으로는 유지, **탈퇴 시 삭제** |
| 온보딩 입력(user_profiles) | 탈퇴 시 삭제 |
| 감사 로그 | 법정 보관기간 동안 유지 후 삭제 (식별 정보 제외) |

`users.mydata_connected = FALSE` 전환 시 위 처리를 비동기 작업으로 실행하고 완료 여부를 기록한다.

## 4. 동의 관리

- 동의 항목: 가맹점명·사업자번호, 적요·거래메모, 상품(구매)분류 — 항목별 개별 동의.
- 동의 상태는 `mydata_consents` 테이블에 시점과 함께 저장하고, 철회 즉시 해당 필드 기반 분류를 중단한다(비-텍스트 대체 경로 사용).
- 1차는 전체 동의 전제(결정표 D-09)이나, 동의 상태 저장 구조는 1차부터 둔다.

## 5. 테스트 데이터

- 직접 만든 테스트 데이터(user_001~003)는 **실제 개인 정보를 사용하지 않는다.** 실제 거래에서 파생한 값이 있다면 비식별화한 뒤 사용한다.
- 마이데이터 표준 API 규격의 필드 구조만 따른다.

## 6. 미결 사항

- 산출 스냅샷 해지 후 처리 방식(삭제 vs 비식별 통계)
- 법정 보관·파기 기한 확인
- 국외 LLM API 사용 시 개인정보 국외 이전 해당 여부 검토
