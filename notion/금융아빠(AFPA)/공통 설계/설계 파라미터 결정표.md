# 설계 파라미터 결정표

> AFPA — 설계 문서에 흩어져 있던 임계치·가중치·정의를 한 곳에서 관리
> 상태: **초기값 확정(튜닝 대상)**. 근거가 약한 값은 테스트 데이터(user_001~003) 검증 후 조정한다.
> 각 설계 문서는 이 표의 ID를 참조한다.

## 1. 정의 확정

| ID | 항목 | 결정 | 근거 / 비고 |
| --- | --- | --- | --- |
| D-01 | 월 저축액·투자금 | **(a) 당월 신규 납입액** (적금·증권 자동이체 기준) | 소스가 명확하고 오차가 작음. 잔액 증가분(b)은 평가손익이 섞여 저축 행동을 왜곡 |
| D-02 | 사용자 화면 노출 지표 | **월 여유 자금(Net Cash Flow)** 을 대표 노출. 월 가용 소득(총수입−고정지출)은 내부 중간값 | 목표 배분 가능 예산은 여유 자금이므로 두 값을 병기하면 혼란 |
| D-03 | 월 총수입 | 세후 입금 기준. 정기수입 불명확 시 최근 3개월 입금 평균, 산출 불가 시 NULL(0 강제 금지) | 스키마 문서와 일치 |
| D-04 | ISA 계좌 | **내부 자산(예수금·주식·펀드)으로 분해**해 자산군에 귀속 | 자산 비중의 정확도. 분해 불가 시 투자 자산으로 일괄 처리 |
| D-05 | 금 현물 | 마이데이터로 수집 불가 → **사용자 수동 입력 자산**(수동 자산 항목) | 온보딩 문서의 수동 자산 입력과 연계 |
| D-06 | 현금성 자산(비상금용) | 입출금·CMA만 인정. 페이머니·외화는 제외(보수적) | 산출 로직 2.3과 일치 |
| D-07 | 부채 지표 명칭 | **DSR**로 통일 (DTI 사용 안 함) | 모든 대출 원리금이 분자 |
| D-08 | 분류 우선순위 | 1차 = 구조화 필드(계좌유형·상환방식 코드), 보조 = 텍스트(상품명·가맹점명·적요) | 자산 분류에서는 코드로 대분류, 상품명 키워드는 코드가 모호할 때 세분류에 사용 |
| D-09 | 1차 동의 전제 | 마이데이터 **전체 동의** 전제. 미동의 대체 경로는 2차 이후 | 산출 로직 문서의 전제와 일치 |

## 2. 주기성·임계치 (분류)

| ID | 항목 | 초기값 | 근거 |
| --- | --- | --- | --- |
| P-01 | 정기수입 입금일 허용 편차 | 기준일 **영업일 보정 후 ±3일** | 급여일이 주말·공휴일이면 직전 영업일로 당겨짐(금→월 최대 3일). 기존 ±2일은 연휴 시 누락 |
| P-02 | 고정지출 출금일 허용 편차 | 기준일 **영업일 보정 후 ±3일** | 자동이체는 다음 영업일로 이연(최대 3일). 수입과 같은 기준으로 통일 |
| P-03 | 고정지출 금액 유사성 | 직전 대비 **±10%**, 공과금·통신은 **±30%** | 정액 구독은 고정, 사용량 비례 요금은 변동 허용 |
| P-04 | 주기성 판정 관측 기간 | 최근 3~6개월, **최소 3회 이상** 반복 | 2회는 우연 반복과 구분 불가 |
| P-05 | 이상지출 | 직전 3개월 평균 대비 **+20% 이상 AND 월 소득의 1% 이상** | 소액 카테고리 노이즈 제거 |
| P-06 | 비상금 개월 수 | 기본 **3개월**, 프리랜서·자영업은 **6개월** | 소득 변동성 반영 |

## 3. 가중치 (금융 건강도·잠재력)

### 3.1 금융 건강도

| 항목 | 가중치 | 근거 |
| --- | --- | --- |
| 저축/투자 성향 | 30% | 자산 축적의 직접 원인. 목표 달성의 핵심 |
| 부채 관리 | 30% | 한 번 악화되면 회복이 느리고 파급이 큼. 규제 기준(DSR 40%)이 명확 |
| 비상금 준비 | 20% | 위기 대응력. 충당률 100% 달성 시 이후 추가 이득 체감 |
| 소비 통제 | 20% | 저축성향과 상관이 있어 이중 반영을 피하려 낮게 설정 |

**중복 해소 방침:** 저축/투자 성향(분모: 총수입, 분자: 납입액)과 소비 통제(변동지출/총수입)는 분자가 달라 완전 중복은 아니다. 1차는 유지한다. **2차**(통합 플래너의 순자산 경로 도입 시)에서 순자산 증가율을 도입해 '소비 통제'를 대체할지 검토한다. 이에 따라 `consumption_ratio` 컬럼은 유지(진단용)하되 점수 반영 여부만 바뀔 수 있다.

### 3.2 금융 잠재력

| 항목 | 가중치 | 근거 |
| --- | --- | --- |
| 목표 진척 속도 | 35% | 프로젝트 핵심 가치(목표 달성) |
| 저축 여력 | 30% | 추가로 목표에 돌릴 수 있는 현실적 여지 |
| 소득 성장성 | 20% | 추정치라 낮게 |
| 시간 여유 | 15% | 복리·회복 여지 |

> 가중치는 FPSB·금융위 등 **기준점은 인용하되 비율 자체는 팀 설계 값**이다. 문서에 "표준 가중치"라고 쓰지 않는다.

## 4. 리밸런싱 규칙 (2차 통합 플래너)

| ID | 규칙 | 값 |
| --- | --- | --- |
| R-01 | 비상금 우선 | 비상금 충당률 < 100%이면 투자 비중 제안 **0**, 여유 자금을 비상금에 우선 배분 |
| R-02 | 투자 가능 비중 | 충당률 ≥ 100% 이후 잔여 여유 자금 중, 안정형 0~20% / 중립형 20~40% / 공격형 40~60% |
| R-03 | 목표 기간 < 12개월 | 해당 목표 자금은 예금·현금성으로만 배분 |

## 6. 통합 플래너·자율성 파라미터 (2차~)

| ID | 항목 | 초기안 | 비고 |
| --- | --- | --- | --- |
| E-01 | 자산군별 기본 수익률 가정 | **구현 시 확정** (보수적 값, 낙관·기준·보수 3종) | 출처와 갱신 주기를 함께 정해야 함 |
| E-02 | 경로 이탈 임계치 | 누적 적립액이 계획 대비 **10% 이상 부족** 또는 달성 예상 시기 **2개월 이상 지연** | 재설계 트리거(5절)와 동일 계열 |
| E-03 | 시나리오 동시 비교 수 | 최대 **3개** | 화면 복잡도 |
| E-04 | 선제 제안 일일 상한 | 즉시 알림 **1건/일** | 알림 설계와 일치 |
| E-05 | 자율 수준 기본값 | **L0 제안만** | 6차 설계 참조 |

## 6-1. 1차 점수 곡선 (구현 시 정한 가정값)

건강도·잠재력의 항목별 점수 곡선은 이 문서에 수치가 없어 1차 구현에서 아래와 같이 정했다(코드: `backend/app/pipeline/params.py`). 테스트 데이터 검증 후 조정 대상이다.

| ID | 항목 | 값 |
| --- | --- | --- |
| H-01 | 저축/투자 성향 | 월 소득의 30% 이상이면 만점, 비례 |
| H-02 | 부채 관리 | DSR 30% 이하 만점 → 60% 이상 0점 (선형 감소) |
| H-03 | 비상금 준비 | 충당률 100% 만점, 비례 |
| H-04 | 소비 통제 | 변동지출/수입 50% 이하 만점 → 70%에서 50% 득점 → 100% 이상 0점 |
| H-05 | 목표 진척 속도 | 1차 단순 배분: 월 여유 자금을 우선순위 순으로 각 목표의 필요 월 저축액에 채운 비율(남은 금액 가중평균). 목표일 없는 목표는 제외. 목표가 없으면 이 축을 빼고 나머지 3축으로 "기초 잠재력" 산출 |
| H-06 | 저축 여력 | 월 여유 자금이 수입의 30% 이상이면 만점 |
| H-07 | 소득 성장성 | 고용 형태(정규직 0.6 / 프리랜서·자영업 0.5 / 무직 0.2) + 나이 보정(30세 미만 +0.2, 40세 미만 +0.1, 50~59세 −0.1, 60세 이상 −0.2). 관측 6개월 이상이면 소득 추세와 평균 |
| H-08 | 시간 여유 | 목표까지 평균 10년 이상이면 만점. 목표가 없으면 (60 − 나이)년 |
| H-09 | 이상 지출 증가액 기준 | P-05의 "월 소득 1% 이상"은 카테고리 **증가액** 기준으로 해석 |

## 6-2. 2차 구현에서 정한 값 (코드: `backend/app/pipeline/params.py`)

E-01·E-02·E-03은 위 6절의 초안을 다음 값으로 구현했다. "G-" 값은 결정표에 수치가 없어 구현 시 정한 가정값이며 테스트 데이터 검증 후 조정한다.

| ID | 항목 | 구현 값 |
| --- | --- | --- |
| E-01 | 자산군별 기본 수익률 | 2차는 목표 적립금을 예금·현금성으로 굴린다고 가정: **보수 연 2% / 기준 3% / 낙관 4%** (세전, 월복리). 기본 경로는 보수 값. 3차에서 실제 상품 금리·세후 효과로 교체 |
| E-02 | 경로 이탈 임계치 | 월 여유 자금이 계획 대비 **±10%** 변화, 또는 목표 달성 예상 시기 **±2개월**, 또는 목표 변경 → 재설계 **제안**(승인 후 적용). 같은 사유 거절 후 **30일** 재제안 금지 |
| E-03 | 시나리오 동시 비교 수 | 최대 3개 |
| G-01 | 비필수 카테고리 절감률 | 카페/간식·쇼핑·문화/여가·기타 평균 지출의 **15%** (필수 카테고리 식비·교통·의료/건강은 급증분 복구만 제안) |
| G-02 | 후보 최소 규모 | 월 절감액이 **월 소득의 0.5% 또는 10,000원 중 큰 값** 미만이면 제외 |
| G-03 | 비상금 우선 적립 속도 | 부족분을 **12개월** 안에 채우는 속도(월 여유 자금을 넘지 않음). 월 적자이면 적자 해소가 먼저 |
| G-04 | 과다 현금 이동 | 비상금 + 한 달 필수 지출을 뺀 현금성 자산이 **100만 원 이상**이면 제안. 금리 가정: 입출금 0.1% → 저축성 3.0% |
| G-05 | 이행 자동 판정 | 수락 이후 완결된 달의 지출이 절감 목표의 **80% 이상** 줄면 완료. 구독은 해당 달 결제가 없으면 완료 |
| G-06 | 제안 만료 | 응답 없이 **30일** 지나면 만료 |
| G-07 | 일회성 성격 카테고리 | 초기 목록: 의료/건강 (소비 변화 설계의 "경조사·여행·의료 등" 확정 전 값) |
| G-08 | 소비 변화 판정 | 급감 −20%, 정기결제 금액 상승 +10%, 수입 변화 ±10%. 후보 판정은 P-05(+20% & 증가액 월 소득 1% 이상)를 따른다 |
| G-09 | 알림 | 즉시 알림 하루 1건(초과분은 일일 요약), 같은 이벤트 7일 중복 억제 |

## 6-3. 변화 감시 에이전트 값 (코드: `backend/app/pipeline/params.py`)

프로필 변화로 볼 최소 폭. 구현 시 정한 가정값이며 테스트 데이터 검증 후 조정한다.

| ID | 항목 | 구현 값 |
| --- | --- | --- |
| A-01 | 월 소득 변화 | **±5%** |
| A-02 | 월 여유 자금 변화 | **±10%** 그리고 1만 원 이상 (계획 이탈 기준 E-02와 같은 폭) |
| A-03 | 순자산 변화 | **±5%** |
| A-04 | 재무 건강 점수 변화 | **±5점** |
| A-05 | DSR·비상금 충족률 변화 | **±5%p** |
| A-06 | 에이전트 최대 조사 횟수 | 도구 호출 **6회**, 이후에는 도구 없이 결론만 내게 함 |
