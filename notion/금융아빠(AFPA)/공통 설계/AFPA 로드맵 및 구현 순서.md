# AFPA 로드맵 및 구현 순서

> AFPA(AI Financial Planning Agent) — 구현 순서와 단계별 범위의 **기준 문서**
> 다른 문서와 충돌하면 이 문서를 따른다. 수치 기준은 「설계 파라미터 결정표」가 기준이다.

---

## 1. 원칙

- **차수는 구현 순서**다. "MVP"는 별도 의미를 갖지 않는다.
- **1차**는 일반 금융 플랫폼 수준의 기능(연동·진단·분석·목표 관리)이다.
- **2차부터 agent**다. 먼저 agent의 뼈대(목표 → 경로 → 이행 추적 → 갱신)를 만들고, 이후 차수가 그 위에 도메인 모듈(예적금, 대출·부동산, 투자)을 얹는다.
- 도메인별로 따로 만든 기능을 합치는 방식이 아니라, **통합 플래너 하나가 도메인 모듈을 선택지로 호출**하는 구조로 확장한다.
- 규제·제도 판정은 **코드의 규칙표**가 맡는다(LLM은 계산·판정하지 않음).

## 2. 차수별 범위

| 차수 | 이름 | 핵심 내용 | 외부 데이터 | 마이데이터 |
| --- | --- | --- | --- | --- |
| **1차** | 기본 플랫폼 | 연동, 자동 분류, 금융 프로필(건강도·잠재력), 수입·지출·자산 분석, 목표 입력·관리·달성 가능성 | 없음 | 수신·카드·증권 |
| **2차** | **통합 플래너** | 목표별 자산 성장 경로, 시나리오(What-if), Action Plan(소비 절감·저축 조정·자산 리밸런싱), 이행 추적, 소비 변화 모니터링, 단순 재설계 | 없음 | 1차와 동일 |
| **3차** | **규제·제도 엔진 + 예·적금** | 규칙표(DSR/LTV·자격 요건·세제), 금융 정보 수집 시작, 예·적금 전략, 금융 환경 변화 모니터링 | 시작 | **대출 추가** (DSR 계산용) |
| **4차** | **대출·부동산** | 구매력 분석, 전세·월세·매매 비교, 대출 한도·상환 전략, 청약, 취득 비용 포함 자금 계획 | 시세·규제 수치 | 연금·보험·페이 등 확장 |
| **5차** | 투자 자산 배분 | 투자 성향, 자산 배분, 리밸런싱, 연금·절세 포트폴리오 (종목 추천 없음) | 시장 데이터 | — |
| **6차** | **자율성 고도화** | 선제 제안(proactive), 재설계 자동화 범위 확대, 이행 이력 기반 개인화 | — | — |

### 순서의 이유

| 결정 | 이유 |
| --- | --- |
| 2차 = 통합 플래너 | 외부 데이터 없이 만들 수 있고, 이후 모든 도메인이 이 경로 위에 얹힌다. 시나리오와 이행 추적을 일찍 넣어야 "관리하는 agent"로 성립한다. |
| 3차 = 규칙 엔진 + 예·적금 | 대출·부동산이 규칙표(DSR/LTV, 자격 요건)에 의존한다. 외부 수집 파이프라인을 구조가 가장 단순한 예·적금으로 먼저 검증한다. 세제(ISA·IRP·연금저축)도 상품 규칙으로 이 단계에 포함한다. |
| 3차에 대출 데이터 추가 | DSR 계산에 보유 대출 원리금이 필요하다. 4차까지 미루면 규칙 엔진을 검증할 수 없다. |
| 4차 부동산이 5차 투자보다 앞 | "내 집 마련"이 가장 대표적인 목표이며 서비스의 핵심("자산을 안정적으로 늘린다")이다. 투자는 규제·법적 부담이 가장 크고, 저축·대출·부동산 경로가 잡힌 뒤에야 투자 여력이 의미를 갖는다. |
| 6차 별도 | 자율성은 앞 차수의 씨앗(이행 추적, 단순 재설계, 환경 변화 알림)을 묶어 완성한다. |

## 3. 자율성의 단계적 도입

| 차수 | 도입되는 자율 기능 |
| --- | --- |
| 2차 | 이행 추적, 소비·목표 변경에 따른 재계산 후 **제안**(승인 후 적용) |
| 3차 | 금융 환경 변화 감지·알림, 변화 반영 재설계 제안 |
| 4~5차 | 도메인별 선제 알림(대출 한도 변화, 청약 시점 등) |
| 6차 | 선제 제안 통합, 승인 범위 사용자 설정(제안만 / 소액 자동 / 승인 후 실행), 개인화 |

## 4. 프로젝트 ↔ 차수 매핑

| 프로젝트(노션) | 차수 |
| --- | --- |
| 사용자 금융 프로필 / 1차 MVP 버전 | 1차 |
| 목표 관리 | 1차 (유형 분화·부동산 목표는 4차) |
| planning-1차 (기본 분석) | 1차 |
| **planning-2차 (통합 플래너)** | **2차** |
| 사용자 소비 변화 모니터링 | 2차 |
| 사용자 목표 관련 금융 정보 수집 | 3차 |
| planning-3차 (규제·제도 엔진 + 예·적금) | 3차 |
| 금융관련 정보 변화 모니터링 | 3차 |
| 모니터링 결과 기반 계획 재설계 | 2차(단순) → 3차(환경 변화) → 6차(선제) |
| planning-4차 (대출·부동산) | 4차 |
| planning-5차 (투자) | 5차 |
| **planning-6차 (자율성)** | **6차** |

선행 관계(노션 속성 기준): 목표 관리 → planning-1차 → planning-2차 → (소비 변화 모니터링) / 정보 수집 → planning-3차 → 환경 변화 모니터링 → 재설계, planning-3차 → planning-4차 → planning-5차 → planning-6차.

## 5. 1차 범위

**포함**
- 온보딩 입력 + 마이데이터(수신·카드·증권, 테스트 데이터) 불러오기
- 데이터 자동 분류(자산·부채·수입·고정지출·변동지출), 동의 전제 전체 데이터 버전
- 금융 프로필 산출(6개 엔진, 건강도·잠재력)
- 수입·지출 분석, 자산 현황 분석, 현금 흐름
- 목표 입력·관리, 필요 자금 계산, 달성 가능성 분석(단순형)

**제외 (2차 이후)**
- Action Plan, 자산 리밸런싱, 지출 개선 제안, 시나리오, 이행 추적, 소비 변화 모니터링
- 외부 데이터 기반 기능 전부

## 6. 데이터 수집 범위

| 범위 | 포함 | 도입 차수 |
| --- | --- | --- |
| 기본 | 은행 수신, 카드, 증권 | 1차 |
| 대출 | 은행·캐피탈 대출, 카드론 | 3차 |
| 확장 | 연금(IRP 등), 보험, 전자금융(페이), 통신 | 4~5차 |
| 장기 | 신용평가(CB), 국세·건보 등 공공 마이데이터 | 6차 이후 검토 |

## 7. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 2차 통합 플래너의 설계 난이도 | 도메인 모듈이 붙기 전에는 단순 규칙 경로(저축 + 단순 수익률 가정)로 시작, 고도화는 3차 이후 |
| 4차 부동산 데이터 확보 | 필요한 값만 규칙표로 시작, 실시간 시세 연동은 이후. 소스는 3차 착수 전 확인 |
| 5차 규제 부담 | 법무 검토를 5차 착수 전 완료, 자산군 비중 제안에 한정 |
| 규칙표 값의 최신성 | 값마다 출처·기준일을 두고 환경 변화 모니터링과 연계(3차) |
