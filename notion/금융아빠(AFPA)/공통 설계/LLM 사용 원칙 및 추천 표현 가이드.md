# LLM 사용 원칙 및 추천 표현 가이드

> AFPA — 코드와 LLM의 역할 경계, 호출 최적화, 추천 표현 수위
> 상태: **초안**

---

## 1. 역할 경계

| 영역 | 담당 | 이유 |
| --- | --- | --- |
| 금액·비율·점수 계산, 목표 달성 시기 | **코드(결정적)** | 재현성·검증 가능 |
| 분류 1~2단계(코드·키워드 규칙) | 코드(규칙) | 비용·속도 |
| 분류 3단계(불명확 가맹점) | **LLM** | 규칙으로 못 푸는 경우에 한정 |
| Action Plan 초안 구성·우선순위 | LLM + 코드 도구 호출 | 계산은 도구로, 조합·설명은 LLM |
| 추천 이유·근거 설명 문장 | **LLM** | 자연어 설명 |
| 규제·자격 요건 판정(DSR 한도, 연령 요건) | 코드(규칙표, 「규제·제도 규칙 엔진 설계」) | 오판 위험 |
| 자산 성장 경로·시나리오·이행 이탈 계산 | **코드(결정적)** | 사용자에게 보이는 핵심 수치 |
| 선제 제안 트리거 감지(6차) | 코드 | 설명·문구만 LLM |

**원칙: LLM은 계산하지 않는다.** 모든 수치는 코드가 계산해 LLM에 전달하고, LLM이 출력한 문장 속 수치는 입력 수치와 일치하는지 검증한다.

## 2. 분류 4단계 호출 범위

| 단계 | 방법 | LLM |
| --- | --- | --- |
| 0 | 가맹점명 유무 분기 | 없음 |
| 1 | 코드·정확매칭 | 없음 |
| 2 | 가맹점명 키워드·패턴 규칙 | 없음 |
| 3 | 불명확 상호 추론 | **호출** (캐시 미스 시) |
| 4 | 사용자 직접 수정 | 없음 |

### 규칙의 정체와 관리

"규칙"은 **매핑 사전**이다: `가맹점명 키워드/정확명 → 카테고리`, `계좌유형 코드 → 자산 분류`.
- **초기 시드:** 문서의 키워드 목록 + 테스트 데이터 가맹점 목록으로 구축
- **확장:** LLM이 3단계에서 판별한 결과를 후보로 저장 → 검수 후 사전에 편입(자동 승격 금지)
- **사용자 수정:** 4단계 수정 내역은 `merchant_category_overrides`에 저장, 이후 1단계에서 즉시 적용

### 호출 최적화
- 가맹점명 정규화(지점명·괄호 제거) 후 **캐시 키**로 사용
- 같은 상호는 사용자 간 공유 캐시 가능(가맹점명 단독이라 개인정보 아님)
- 배치 호출로 묶어 처리, 실패 시 "미분류" 후 사용자 확인 유도

## 3. 입력 데이터 제한

개인정보 문서의 LLM 전달 범위를 따른다: 식별 정보·계좌/카드번호 금지, 가맹점명은 금액·일시와 분리, 그 외는 집계 수치.

## 4. 출력 검증

- 구조화 출력(JSON 스키마)으로 받는다.
- Action Plan의 금액·기간은 코드가 재계산해 불일치 시 폐기·재생성한다.
- 규제상 금지 표현(5절)은 후처리 필터로 차단한다.

## 5. 추천 표현 가이드

| 구분 | 허용 | 금지 |
| --- | --- | --- |
| 투자 | 자산군 비중 제안, 성향별 일반 정보 | **개별 종목·펀드 추천**, 수익 보장·단정 표현 |
| 상품 | 조건 비교·계산 결과 제시 | "무조건 유리", "반드시 가입" |
| 대출 | 한도·상환 시뮬레이션 | 대출 권유 |
| 근거 | 사용자 수치·출처·기준일 명시 | 출처 없는 수치 |

**고지 문구(안):** "AFPA의 제안은 입력된 데이터를 기반으로 한 참고 정보이며 투자·대출 권유가 아닙니다. 최종 판단은 본인의 책임입니다."
투자 자문 관련 규제 해당 여부는 5차(투자 전략) 착수 전 **법무 검토**한다.

## 6. 장애·폴백

- LLM 실패: 분류는 "미분류 → 사용자 확인", 설명은 템플릿 문장으로 대체
- 비용 상한: 사용자당 일일 호출 상한 설정(수치는 운영 단계에서 결정)

## 7. 미결 사항

- 사용 모델과 비용 예산
- 프롬프트·결과 로그 보관 정책(개인정보 문서와 연동)
