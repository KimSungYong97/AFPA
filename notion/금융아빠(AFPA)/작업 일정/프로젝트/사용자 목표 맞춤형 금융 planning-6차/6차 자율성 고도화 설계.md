# 6차 자율성 고도화 설계

> AFPA — 사용자가 묻기 전에 먼저 제안하고, 이행 이력으로 개인화하는 agent 완성 단계
> 상태: **초안**. 2~5차의 이행 추적, 재설계, 환경 변화 알림이 선행 조건이다.

---

## 1. 개요

앞 차수에서 만든 기능은 대부분 **사용자가 요청하거나 이벤트가 발생했을 때** 동작한다. 6차는 이를 묶어 agent가 **스스로 기회와 위험을 찾아 제안**하게 한다. 자율성의 범위는 사용자가 정한다.

## 2. 선제 제안 (Proactive)

| 트리거 | 예시 |
| --- | --- |
| 경로 이탈 임박 | "이 속도면 3개월 뒤 목표 달성 시기가 늦어질 수 있어요" |
| 기회 | 더 유리한 상품 출시, 신규 정책 대상 자격 충족(연령·소득 변화), 세제 한도 소진 임박 |
| 위험 | DSR 임계 접근, 비상금 충당률 하락, 만기·금리 변동 시점 도래 |
| 시점 | 청약 납입 시점, 연말 공제 한도 정리, 대출 갱신·금리 재산정 |
| 생애 이벤트 | 소득 변화, 이사·결혼 등 목표 변경 징후(거래 패턴) |

처리: 트리거 감지(코드) → 영향·효과 계산(코드) → 제안 구성·설명(LLM) → 알림(「알림 설계」).
선제 제안은 근거 수치와 **"왜 지금 알리는지"** 를 반드시 포함한다.

## 3. 자율 수준 (사용자 설정)

| 수준 | 동작 | 기본값 |
| --- | --- | --- |
| L0 제안만 | 모든 변경은 사용자 승인 후 | 기본 |
| L1 소액 자동 | 사전 한도 내 계획·배분 갱신은 자동 적용 후 통보 (취소 가능) | 선택 |
| L2 승인 후 실행 연계 | 승인 시 실행 단계(자동이체 설정 안내 등)까지 연결 | 선택 |

- **계획 내부 갱신**(경로·배분 재계산)과 **실제 금융 행위**(이체·가입·해지)는 구분한다. agent는 실제 금융 행위를 **직접 실행하지 않는다**(실행은 사용자 또는 금융사 화면에서).
- 자동 적용 대상에서 제외: 대출 신청·해지, 투자 매매, 상품 가입·해지.

## 4. 개인화

이행 추적(2차)의 이력으로 제안 방식을 조정한다.

| 학습 대상 | 반영 |
| --- | --- |
| 거절·미이행 패턴 | 같은 유형 제안의 빈도·강도 조정, 대안 우선 제시 |
| 실행 성공률이 높은 행동 유형 | 우선순위 상향 |
| 선호(위험 감수, 소비 우선순위) | 목표 간 배분 제안, 절감 항목 선택 |
| 알림 반응 | 시간대·빈도·채널 최적화 |

학습은 **사용자 단위 설정값 조정** 수준으로 시작한다(모델 재학습 없음). 개인화 근거는 사용자에게 열람·초기화 가능해야 한다.

## 5. 재설계 자동화 범위 확대

「계획 재설계 설계」의 트리거를 6차에서 확장한다.
- 선제 제안과 재설계를 한 흐름으로 통합(감지 → 재평가 → 새 계획 → 승인).
- L1 사용자는 임계 이내 경미한 변경(예: 월 배분 ±N%)을 자동 반영.

## 6. 안전장치

| 항목 | 방침 |
| --- | --- |
| 과잉 알림 | 빈도 제한, 같은 사유 재제안 제한(「알림 설계」), 선제 제안은 일일 상한 |
| 오판 | 근거 수치 재계산 검증, 낮은 확신 제안은 "참고" 등급으로 하향 |
| 규제 | 투자·대출 관련 선제 제안도 5절 추천 표현 가이드 적용 |
| 개인정보 | 개인화 데이터는 최소 수집, 해지 시 파기(「개인정보 보호 및 데이터 파기 정책」) |
| 되돌리기 | 자동 반영된 변경은 이전 버전(`plan_versions`)으로 복원 가능 |

## 7. 평가

선제 제안 수용률, 억제된 알림 수, 경로 이탈 감소율, 사용자 수동 변경 빈도, 개인화 후 거절률 변화(「평가 기준 및 성능 대시보드」에 지표 추가).

## 8. 미결 사항

- 자율 수준 L1의 자동 적용 한도 값
- 개인화 학습 범위와 설명 가능성 요구 수준
- L2 연계 범위(금융사 연동 가능성, 규제)
