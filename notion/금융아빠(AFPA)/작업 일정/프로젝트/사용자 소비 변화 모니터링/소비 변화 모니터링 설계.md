# 소비 변화 모니터링 설계

> AFPA(AI Financial Planning Agent) — 마이데이터 거래내역 기반 소비 변화 감지 설계 (기획 문서 없어 초안)
> 상태: **초안** (기획 문서 기반 정리. 세부 값·기준은 팀 논의 후 확정)

---

## 1. 개요

> ⚠️ 별도 기획 문서가 없어, 「금융 프로필 산출 로직」의 소비 진단(이상지출 감지)과 스냅샷 구조를 바탕으로 작성한 초안이다. 범위 확정 필요.

마이데이터 동기화 때마다 소비 패턴 변화를 감지하고 목표 진행에 미치는 영향을 계산해 「계획 재설계」에 전달한다.

## 2. 감지 항목

| 항목 | 기준(안) |
| --- | --- |
| 카테고리 급증/급감 | 최근 3개월 평균 대비 편차 ±20% |
| 총지출·소비 성향 지수 변화 | 전월 스냅샷 대비 |
| 고정지출 변화 | 신규 정기결제 발생·금액 변동 |
| 수입 변화 | 정기수입 금액·입금일 변동 |
| 건강도·잠재력 점수 변화 | 스냅샷 시계열 비교 |

## 3. 처리 흐름

1. 동기화 후 신규 `financial_snapshots` 생성
2. 직전 스냅샷·3개월 평균과 비교
3. 임계치 초과 항목 → 이벤트 생성
4. 목표 영향 계산 (월 여유 자금 변화 → 목표 달성 시기 변화)
5. 알림 + 재설계 트리거

## 4. 출력 예

- "이번 달 식비가 3개월 평균보다 28% 늘었어요. 이 속도면 목표 달성이 2개월 늦어집니다."

## 5. 일시적 변화 vs 구조적 변화 판정

핵심은 **일회성 지출과 지속 변화를 구분**하는 것이다. 구조적 변화만 알림·재설계 대상이 된다.

| 판정 | 조건(초기값, 결정표 P-05 기반) |
| --- | --- |
| 이상 지출 후보 | 카테고리 지출이 직전 3개월 평균 대비 **+20% 이상 AND 월 소득의 1% 이상** |
| **구조적** | 후보 상태가 **2개월 연속** 지속, 또는 신규 정기결제(고정지출) 발생·금액 상승 |
| **일시적** | 후보가 **1개월만** 발생하고 다음 달 평균 범위로 복귀, 또는 사용자가 "일회성"으로 지정, 또는 경조사·여행·의료 등 일회성 성격 카테고리 |
| 확정 보류 | 데이터 1개월분만 있는 경우(신규 사용자) → 판정하지 않고 관찰 |

- 일시적 변화는 낮음 등급(주간 요약)으로만 안내, 구조적 변화는 중간 이상 등급.
- 사용자가 "일회성" 지정한 거래는 평균 산출에서 제외(학습 반영).

## 6. 모니터링 주기와 알림

- **주기:** 마이데이터 동기화 직후 실행(동기화 주기와 동일). 스냅샷 생성 → 비교 → 이벤트.
- **알림:** 「알림 설계」의 소비 변화 유형·빈도 제한 규칙을 따른다. 알림 채널은 MVP에서 앱 내 알림 센터.
- **재설계 연계:** 월 여유 자금 **±10% 이상** 변화 또는 목표 달성 시기 **±2개월 이상** 변화 시 재설계 트리거.

## 7. 착수 시점

내부 데이터만 사용하므로 외부 데이터 의존이 없다. 스냅샷 이력이 2~3개월 이상 쌓여야 의미가 있어 **2차**에 구현하되, 스냅샷 저장은 1차부터 시작한다.

## 8. 미결 사항

- 일회성 성격 카테고리 목록 확정
- 신규 사용자(이력 부족)의 비교 기준 대체안 (동일 연령·소득대 평균 사용 여부)
