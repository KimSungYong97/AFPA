# 사용자 데이터 입력(온보딩) 설계

> AFPA — 마이데이터로 얻을 수 없는 정보를 받는 온보딩 흐름
> 관련 문서: 「사용자 정보 DB 스키마 설계」(`user_profiles`, `mydata_consents`), 「개인정보 보호 및 데이터 파기 정책」, 「설계 파라미터 결정표」
> 상태: **초안**

---

## 1. 원칙

- 마이데이터로 알 수 있는 값(소득·지출·잔액)은 **입력받지 않는다.**
- 입력은 **정책·상품 자격 판정**과 **마이데이터 밖 정보**에 한정한다.
- 필수 항목은 최소화하고, 건너뛴 항목은 나중에 입력하도록 안내한다.

## 2. 입력 항목

### 2.1 기본 인적·환경 정보 (`user_profiles`)

| 항목 | 필수 | 입력 형식 | 검증 | 용도 |
| --- | --- | --- | --- | --- |
| 생년월일 | 필수 | 날짜 선택 | 만 19세 이상(서비스 대상), 미래일 불가 | 청년 정책 대상 판별 |
| 고용 형태 | 필수 | 선택(정규직/프리랜서/자영업/무직) | — | 소득 안정성, 비상금 개월 수(결정표 P-06) |
| 거주 형태 | 필수 | 선택(자가/전세/월세) | — | 주거 관련 정책·목표 |
| 월세/임대료 | 월세 선택 시 필수 | 숫자(원) | 0 초과 | 월세 공제, 고정지출 교차 확인 |
| 거주 지역(시/도, 구/군) | 필수 | 선택 | 시/도 선택 시 구/군 목록 제한 | 지역별 정책 |
| 성별 | 선택 | 선택(미입력 허용) | — | 통계·정책 판별에 필요한 경우에만 |
| 투자 성향 | 선택(1차) | 선택(안정형/중립형/공격형) | 미입력 시 중립형 가정 | 리밸런싱 비중(결정표 R-02) |

### 2.2 수동 자산 (마이데이터에 없는 자산)

| 항목 | 설명 |
| --- | --- |
| 보유 현금 | 지갑·집에 보관한 현금 (비상금 계산에는 포함하지 않음, 참고용) |
| 금 현물 | 수량·평가액 직접 입력 (결정표 D-05) |
| 기타 자산 | 항목명·금액 |

수동 자산은 `manual_assets`(항목, 금액, 입력일)로 저장하고 갱신 일자를 표시한다. 오래된 값(예: 6개월 이상)은 갱신 안내.

### 2.3 마이데이터 연동·동의

| 단계 | 내용 |
| --- | --- |
| 기관 선택 | 1차 범위(은행·카드·증권)의 기관 선택 |
| 동의 | 가맹점명·사업자번호 / 적요·거래메모 / 상품분류 **항목별 동의** 화면 (`mydata_consents` 저장) |
| 안내 | 동의하지 않으면 해당 기능의 정확도가 낮아짐을 명시 (1차는 전체 동의 전제) |

### 2.4 목표 입력

온보딩 마지막에 「목표 관리」의 목표 생성 화면으로 연결한다(목표 없이도 프로필은 조회 가능).

## 3. 흐름

1. 계정 생성 → 2. 기본 정보 입력 → 3. 마이데이터 연동·동의 → 4. 수동 자산 입력(선택) → 5. 데이터 분류 결과 확인(사용자 수정) → 6. 금융 프로필 확인 → 7. 목표 입력

**분류 결과 확인 단계:** 자동 분류가 불확실한 항목(미분류·낮은 확신도)을 모아 사용자가 한 번에 확정할 수 있게 한다(분류 4단계 사용자 수정, 수정 내역은 이후 자동 적용).

## 4. 수정·갱신

- 모든 입력값은 설정에서 수정 가능, 수정 시 `updated_at` 갱신
- 고용 형태·거주 형태·월세 변경 시 프로필 재산출 트리거
- 투자 성향 설문 도입 시(5차 투자 전략) 자가입력값을 설문 결과로 대체

## 5. 미결 사항

- 비회원(체험) 모드 제공 여부
- 연령 하한(만 19세) 정책 확인
- 지역 목록 데이터 출처
