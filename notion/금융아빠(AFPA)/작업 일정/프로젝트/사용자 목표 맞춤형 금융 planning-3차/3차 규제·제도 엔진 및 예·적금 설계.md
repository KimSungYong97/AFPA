# 3차 규제·제도 엔진 및 예·적금 설계

> AFPA — 규칙 엔진 구축, 외부 정보 수집 시작, 예·적금 전략을 통합 플래너의 첫 도메인 모듈로 연결
> 상태: **초안** (2차 구현에서 확정된 모듈 인터페이스·평가 방식에 맞춰 4·7절 갱신)

---

## 1. 개요

3차는 두 가지를 한다.
1. **기반:** 규제·제도 규칙 엔진과 외부 정보 수집 파이프라인을 만든다.
2. **도메인:** 구조가 가장 단순한 예·적금을 첫 모듈로 올려 파이프라인과 모듈 인터페이스를 검증한다.

## 2. 기반 구축

| 항목 | 내용 | 문서 |
| --- | --- | --- |
| 규제·제도 규칙 엔진 | 대출 규제, 자격 요건, 세제 규칙표와 판정 함수 | 「규제·제도 규칙 엔진 설계」 |
| 금융 정보 수집 | 상품·정책·시장 정보 수집, 정규화, 변경 추적 | 「금융 정보 수집 설계」 |
| 환경 변화 모니터링 | 규칙표·상품·금리 변경 감지, 영향도 계산 | 「금융 환경 변화 모니터링 설계」 |
| 마이데이터 확장 | **대출 정보** 수집 추가 (DSR 계산용) | 「데이터 자동 분류 로직」 부채 분류 활성화 |

## 3. 예·적금 모듈

통합 플래너에 **선택지**를 제공한다(「2차 통합 플래너 설계」 6절).

- **예·적금 추천:** 목표 기간·금액·월 납입 가능액·자격 요건(규칙 엔진 `eligible_products`)으로 후보 필터링
- **금리 비교:** 기본·최고·우대금리 조건 비교
- **우대금리 분석:** 사용자가 충족 가능한 우대 조건(급여이체, 카드 실적 등)만 반영한 **실질 예상 금리**
- **만기 시뮬레이션:** 월 납입액·기간·금리 → 만기 수령액, 세후 이자, **목표 달성 시기 변화**
- **예·적금 리밸런싱:** 기존 가입 상품보다 유리한 상품이 있을 때 갈아타기 제안(중도해지 손실 고려)

### 3.1 계산식 (안)
- 정기예금(단리): `이자 = 원금 × 연이율 × 기간(년)`
- 정기적금(단리): `이자 = 월납입액 × 연이율 × (n(n+1)/2) / 12` (n = 납입 개월 수)
- 세후 효과는 **규칙 엔진 `tax_effect`** 가 계산한다(일반과세, 비과세·세금우대 상품 포함). 문서에 세율을 고정하지 않는다.

### 3.2 세제 연계
- ISA, IRP·연금저축 등 **절세 계좌의 활용 여력**(한도 잔여, 공제 효과)을 예·적금 선택지와 함께 제시한다.
- 투자 상품 구성은 5차에서 다룬다.

## 4. 통합 플래너와의 연결 (2차에서 확정된 계약)

예·적금 모듈은 통합 플래너를 고치지 않고 **꽂는다**. 2차에 만든 인터페이스를 그대로 쓴다(「2차 통합 플래너 설계」 6절).

| 3차 구성 | 연결 방식 |
| --- | --- |
| 예·적금 추천·갈아타기 | `CandidateProvider`를 구현해 등록한다. 후보 키는 `deposit:{상품ID}`처럼 안정적으로 짓는다(수락·거절 이력이 키에 붙는다) |
| 만기 시뮬레이션·세후 효과 | 후보의 `change.goal_returns = {목표: {annual_return: 우대 반영 실질 금리, tax_rate: 규칙 엔진 `tax_effect`가 준 세율}}`. 경로 엔진이 목표별 수익률·세율로 굴려 **달성 시기 변화**를 계산한다 |
| 가입 자격·한도 판정 | 규칙 엔진 `eligible_products`를 `RuleChecker`로 등록한다. 불가 판정은 `Eligibility(False, rule_id, reason)` — 후보는 `excluded`로 분리되고 사유가 사용자에게 보인다. `facts`(나이·고용·거주·소득 등)는 플래너가 채워 준다 |
| 같은 목표의 중복 상품 | `conflict_group`(예: `deposit:전세`)으로 묶어 "함께 하기 어려움"으로 표시 |
| 금융 환경 변화 | 금리·상품·규칙 변경 이벤트를 **변화 감시 에이전트**의 조사 도구로 추가한다(예: `get_market_changes`). 영향도 계산은 코드, 해석·설명은 에이전트 |
| 대화 | 대화 에이전트에 상품 비교·"이 상품이면 얼마나 빨라져요?" 도구를 추가한다(인자는 코드가 검증) |

- 선택지는 경로에 반영되어 **"이 상품으로 가입하면 목표가 N개월 빨라짐"** 으로 표시된다.
- 규칙 엔진에서 불가 판정을 받은 상품은 사유와 함께 제외한다.
- 거절 학습·사후 보고는 같은 후보 키로 동작하므로 예·적금 후보에도 그대로 적용된다.

## 4-1. 완료 기준 (평가 세트)

3차는 아래가 `backend/evals/`와 테스트에 들어가야 끝난다(「평가 기준 및 성능 대시보드」 4-1절).
- 규칙표 골든 케이스: 연령·소득 경계에서 가입 가능/불가 판정이 규칙 ID와 함께 일치(회귀 실패 0건)
- 만기 시뮬레이션 골든 케이스: 단리 예금·적금 이자·세후 이자 수기 계산과 오차 0
- 에이전트 시나리오: 자격 불가 상품은 후보에 없고 사유가 있다 / 금리 변경 이벤트가 영향받는 사용자에게만 알림 / 같은 상품 후보의 거절 학습

## 5. 출력

- 추천 상품 비교표(근거·기준일), 만기 시뮬레이션, 경로 변화, 규칙 판정 사유

## 6. 미결 사항

- 상품 데이터 소스(금융상품 비교 공시 등)와 갱신 주기
- 우대금리 조건 충족 여부를 마이데이터로 어디까지 판별할 수 있는지
- 규칙표 초기 구축 범위(예·적금 관련 자격·세제에 한정할지)
