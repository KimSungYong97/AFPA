================================================================================
 AFPA 마이데이터 테스트 데이터셋 — 파일별 상세 설명
================================================================================
근거 규격 : 금융분야 마이데이터 표준 API 규격 v202102-1
생성 도구 : backend/scripts/generate_mydata.py  (입력: data/personas.json)
DB 적재   : backend/scripts/seed_data.py (app/pipeline: 자동 분류 → 프로필 엔진 → 스냅샷)
디렉터리  : data/mydata/user_{id:03d}/  (사용자 1명당 폴더 1개, JSON 16개)

--------------------------------------------------------------------------------
0. 공통 사항
--------------------------------------------------------------------------------
■ 응답 래퍼
  모든 JSON은 표준 API 응답 형식을 따른다.
    rsp_code         : "00000" (성공)
    rsp_msg          : "성공"
    search_timestamp : 조회 시각 (yyyyMMddHHmmss)
    + 업권별 payload

■ 날짜/시간 형식
    일자   : yyyyMMdd        (예: 20260807)
    일시   : yyyyMMddHHmmss  (예: 20260807143000)

■ 금액
    모두 KRW 원 단위 정수(또는 소수점 없는 반올림 값).

■ 데이터 기간
    거래성 데이터(입출금/카드승인/납입 등)는 이번 달 포함 최근 6개월치.
    이번 달은 "오늘까지 발생한 만큼"만 생성되며, 카드 승인내역은
    personas.json의 current_month_factor 배율이 적용된다
    (예: 박과소 1.35 → 소비 급증 → 5.5 모니터링 알림 테스트용).

■ 규격 외 내부 필드 (언더스코어 접두사)
    _user.json                    : 사용자 메타 (규격 외 — 시드 스크립트 참조용)
    card_approvals의 _category    : 지출 카테고리 힌트 (식비/쇼핑/교통 등)
    card_approvals의 _is_fixed    : 고정지출 여부 힌트 (구독서비스 true)
    → 실제 마이데이터 응답에는 없는 필드로, 분류 로직(app/pipeline)은 사용하지 않는다.
      정답 라벨로만 쓰이며 scripts/evaluate_classification.py 가 분류 정확도 평가에 사용한다.

■ 정합성 규칙 (생성 시 자동 검증)
    은행 입출금 + 정기예금 + 페이잔액  == persona.profile.deposit
    은행 적금 잔액                      == persona.profile.savings
    금투 평가금액(예수금 포함)          == persona.profile.investment
    IRP 평가금액                        == persona.profile.other_assets
    은행대출 + 리볼빙 + 현금서비스 + 캐피탈 == persona.profile.total_debt

■ 가상 기관 코드
    020 AFPA은행 / 301 AFPA카드 / 247 AFPA증권 / 452 AFPA생명
    901 AFPA페이 / T01 AFPA텔레콤 / 550 AFPA캐피탈 / 560 서울보증보험

--------------------------------------------------------------------------------
1. _user.json  (규격 외 — 사용자 메타)
--------------------------------------------------------------------------------
어댑터/시드 스크립트가 참조하는 인물 정보. 마이데이터 규격에는 없는 파일.
    user_id / name / job / persona_type / description
    monthly_income            : 월 소득
    monthly_fixed_expense     : 월 고정지출 (주거/공과금/보험/통신 합)
    monthly_variable_expense  : 월 변동지출 (≈ 카드 승인 월 합계)
    goals                     : 재무 목표 목록 (DB Goal 테이블로 적재)

--------------------------------------------------------------------------------
2. bank_accounts.json  (은행-001 계좌목록 / 002 기본정보 / 003 추가정보)
--------------------------------------------------------------------------------
수신(예·적금) 계좌. 계좌번호 체계: 110{uid:03d}XXXX
  account_list[]  ← 은행-001
    account_num        : 계좌번호
    is_consent         : 전송요구 동의 여부
    seqno              : 회차번호
    prod_name          : 상품명 (자유입출금통장/정기예금/적금)
    account_type       : 1001 입출금 / 1002 정기예금 / 1003 적금
    account_status     : 01 활동
    is_foreign_deposit : 외화 여부
    is_minus           : 마이너스 약정 여부
  basic_list[]  ← 은행-002
    issue_date         : 개설일
    exp_date           : 만기일 (예금 +365일, 적금 +540일)
    monthly_paid_in_amt: 적금 월 납입액 (김철수 50만 / 이영희 100만)
  detail_list[]  ← 은행-003
    balance_amt        : 현재 잔액  ★ 자산 집계의 원천
    withdrawable_amt   : 출금가능액 (입출금만 잔액과 동일)
    offered_rate       : 적용금리 (입출금 0.1 / 예금 3.2 / 적금 4.5%)

--------------------------------------------------------------------------------
3. bank_transactions.json  (은행-004 거래내역)
--------------------------------------------------------------------------------
입출금통장(…0001)의 6개월 거래. 매월 반복 패턴:
    25일 급여 입금        (trans_type 03, monthly_income 전액)
    25일 월세/관리비 이체 (04, 고정지출의 55%)
    26일 전기/가스/수도   (04, 고정지출의 10%)
    14일 카드대금 출금    (04, monthly_spending)
    1일  적금 자동이체    (07 대체)
  필드: trans_dtime / trans_no / trans_type / trans_class(급여·출금·대체)
        trans_amt(절대값) / balance_amt(거래 후 잔액) / trans_memo
  ★ 어댑터는 memo 기반으로 "월세/관리비", "전기/가스/수도"를 고정지출
    거래로 DB에 적재한다. (급여·카드대금·적금이체는 이중계상 방지로 제외)

--------------------------------------------------------------------------------
4. bank_loans.json  (은행-008 대출목록 / 009 기본 / 010 거래내역)
--------------------------------------------------------------------------------
이영희만 보유 (전세자금대출 1억 2천). 계좌번호 210{uid:03d}0001
  loan_list[]    : prod_name "AFPA 전세자금대출", account_type 3170
  basic_list[]   : last_offered_rate 3.8% / repay_method 01(만기일시상환)
                   repay_date 25일 / repay_account_num(자동이체 계좌)
  detail_list[]  : balance_amt = loan_principal (원금 미상환)  ★ 부채 집계 원천
  trans_list[]   : 매월 25일 이자 납입 (trans_type 02, 원금 0 / 이자만)
                   월 이자 = 잔액 × 3.8% ÷ 12 ≈ 38만원

--------------------------------------------------------------------------------
5. card_list.json  (카드-001 카드목록 / 002 기본정보)
--------------------------------------------------------------------------------
보유 카드: 김철수 1장 / 이영희 2장 / 박과소 3장
  card_id     : CARD{uid:03d}{n:02d} — 승인내역과 연결되는 키
  card_num    : 마스킹된 카드번호
  card_member : 1 본인
  card_type   : 01 신용 / 03 체크 (3번째 카드만 체크)
  card_brand  : 04 국내전용
  annual_fee  : 신용 15,000 / 체크 0
  issue_date  : 박과소만 최근 발급(20240901) — 신규 과소비 서사

--------------------------------------------------------------------------------
6. card_approvals.json  (카드-007 국내승인내역)  ★ 변동지출의 원천
--------------------------------------------------------------------------------
6개월치 승인내역. 월 합계 ≈ monthly_variable_expense(±10% 랜덤).
카테고리별 비중으로 분산 생성 (카테고리당 월 3~8건):
    식비 35% / 쇼핑 20% / 문화·여가 15% / 교통 10% / 카페·간식 10%
    의료·건강 5% / 기타 5%
+ 구독서비스 4건(넷플릭스/유튜브/멜론/쿠팡와우) 매월 1일, _is_fixed=true
  필드:
    card_id / approved_num / approved_dtime
    status        : 01 승인 (취소 없음)
    pay_type      : 01 일시불
    merchant_name : 실존풍 가맹점명 (예: "스타벅스 역삼점")
    merchant_regno: 업종코드 기반 사업자번호 (5812 음식점 등)
    approved_amt  : 승인금액
    foreign_yn    : false (해외승인 없음)
    _category     : (내부) 지출 카테고리 → DB Transaction.category
    _is_fixed     : (내부) 고정지출 여부 → DB Transaction.is_fixed
  ★ 이번 달 = monthly_spending × current_month_factor × 경과일/30
    → 박과소(1.35)는 월말 환산 시 3개월 평균 대비 +35% → 소비 알림 발생

--------------------------------------------------------------------------------
7. card_bills.json  (카드-004/005 청구정보)
--------------------------------------------------------------------------------
매월 14일 결제된 청구서 (도래한 달만).
    charge_month  : 청구 연월 (yyyyMM)
    charge_day    : 14
    charge_amt    : ≈ monthly_spending (100원 단위 반올림)
    paid_out_date : 출금일
  ※ 은행 거래내역의 "AFPA카드 대금" 출금과 짝을 이룬다.

--------------------------------------------------------------------------------
8. card_points.json  (카드-003 포인트)
--------------------------------------------------------------------------------
    point_name         : AFPA포인트
    remain_point_amt   : uid × 3,500 (김철수 3,500 / 이영희 7,000 / 박과소 10,500)
    expiring_point_amt : 500 (60일 내 소멸 예정)
  ※ 현재 DB 적재에는 사용되지 않음 (향후 혜택 분석용).

--------------------------------------------------------------------------------
9. card_loans.json  (카드-009~012 리볼빙/단기/장기 대출)
--------------------------------------------------------------------------------
박과소만 보유.
  revolving_list[]  : 리볼빙 잔액 200만 / 약정금리 17.5% / 최소결제 10%
                      monthly_pay_amt 20만 (매월 최소결제)
  short_term_list[] : 현금서비스 300만 / 금리 18.9% / 45일 전 실행, 45일 후 만기
  long_term_list[]  : 카드론 없음 (빈 배열)
  ★ remain_amt 합계 500만이 부채 집계에 포함된다.

10. invest_accounts.json  (금투-001~004 계좌/기본/거래/상품)
--------------------------------------------------------------------------------
계좌번호 310{uid:03d}0001. investment 총액을 다음처럼 배분:
    예수금(withholdings_amt) 10%
    KODEX 200 ETF            나머지의 60%
    AFPA 글로벌성장펀드       나머지의 40%
  product_list[] : prod_type 401 ETF / 301 펀드,
                   purchase_amt(매입가 = 평가액의 92~95%, 즉 수익 중),
                   eval_amt ★ 자산 집계 원천 (예수금 + eval_amt 합)
  trans_list[]   : 매월 5일 ETF 적립 매수
                   (김철수 20만 / 이영희 50만 / 박과소 5만)
  규모: 김철수 300만 / 이영희 2,500만 / 박과소 50만

11. insurance_list.json  (보험-001~005 목록/기본/자동차/납입)
--------------------------------------------------------------------------------
월 보험료 총액 = 고정지출의 20%.
  김철수·박과소 : 실손의료보험 1건 (전액)
  이영희        : 실손 30% + 자동차보험 35% + 종신보험 35% (3건)
  insu_list[]   : insu_type 01 실손 / 04 자동차 / 05 종신, insu_status 02 정상
  basic_list[]  : face_amt(가입금액) — 종신 1억 / 그 외 3천만
  car_list[]    : 이영희만 — 쏘렌토 하이브리드, 부부한정, 자기부담 20%
  payment_list[]: pay_cycle 1M / pay_date 25일 / pay_amt(월 보험료)
  ★ 어댑터는 payment_list 기준으로 매월 25일 보험료 고정지출 거래를 생성.

================================================================================
 데이터 범위 — 포함/제외 기준
================================================================================
규격 전체가 아니라 AFPA 프로젝트 기능에 필요한 데이터만 선별 생성했다.

■ 판단 기준
  1. 자산 / 부채 / 현금흐름 3가지로 환원 가능한 데이터만 생성
     — AFPA 분석 로직(profile_service, monitoring_service)이 소비하는 형태
  2. 페르소나 서사에 등장하지 않는 상품(해외거래, P2P 등)은 제외
  3. 각 업권의 "목록 → 기본 → 추가 → 거래" 계층 구조는 유지 (규격 형태 보존)

■ 포함 (프로젝트에서 실제 사용)
  ┌────────────────────────────────────────┬────────────────────────────┐
  │ 데이터                                  │ 사용처                     │
  ├────────────────────────────────────────┼────────────────────────────┤
  │ 은행 수신잔액, 금투/IRP 평가액, 페이잔액 │ 5.1 자산 현황·건강도       │
  │ 은행/카드/캐피탈 대출 잔액              │ 부채 비율 계산             │
  │ 카드 승인내역 (6개월)                   │ 5.5 소비 변화 감지 ★핵심   │

■ 제외 (규격에는 있으나 미생성)
  - 인증/인가 API (인가-001~006, 지원-001~002)
      : 토큰 발급·기관 목록 등 통신 절차용 — 정적 테스트 데이터와 무관
  - 은행 : 투자상품계좌(005~007, 은행 펀드 — 금투 업권으로 대체), 해외거래
  - 카드 : 해외승인(008), 결제예정정보 일부, 포인트 상세내역
  - 보험 : 특약정보(003), 자동차보험 거래내역 세부, 보험계약대출
  - 금투 : 연금계좌 상세 (IRP 업권으로 대체)
  - 전금 : 후불(하이브리드) 결제, 계좌 연결정보
  - 통신 : 소액결제 내역 상세
  - P2P·인수채권 업권 전체 : 페르소나 시나리오에 없음

■ 확장 방법
  기능 추가 시(예: 카드 혜택 분석 → 포인트 상세, 보험 리모델링 → 특약정보)
  generate_mydata.py에 생성 함수를 추가하고 GENERATORS dict에 등록하면 된다.

 재생성 / DB 적재 방법
